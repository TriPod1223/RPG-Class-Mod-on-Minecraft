# Анимации игрока (0.9, PlayerAnimator)

Зависимость: **PlayerAnimator** (KosmX, `player-animation-lib-forge:1.0.2-rc1+1.20`) — обязательная (`mods.toml`: `playeranimator`, `build.gradle`: репозиторий `maven.kosmx.dev`).
Если установлен **Epic Fight**, анимации не отправляются (у него своя система). Отключить: конфиг `animations.playerAnimations = false`.

## Как это работает
* Сервер: `Ability.tryUse` после успешного применения вызывает `PlayerAnims.play` → пакет `Packets.PlayAnim(uuid игрока, id анимации)` всем, кто видит игрока, и самому игроку.
* Клиент: `ClientAnims` — один слой (`ModifierLayer`, приоритет 42) на игрока; пакет проигрывает `assets/<ns>/player_animation/<id>.json`. Нет файла — навык просто без анимации.
* По умолчанию анимация = id способности; изменить: `ability.animation("другой_id")`. Для новых классов достаточно положить JSON в `player_animation/`.
* Файлы создаёт `tools/gen_anims.py` (32 анимации, поза-ключи в градусах; редактируйте таблицу `ANIMS` и перезапустите `gen_assets.py`). JSON — формат Emotecraft, их можно открыть/править в Emotecraft/Blender-плагине.
* Эффекты срабатывают мгновенно, поэтому каждая анимация **начинается в момент удара** (замах уложен в нулевой тик) и заканчивается нейтральной позой; удержание позы совпадает с длительностью визуального эффекта.

## Допущения и непроверенное
* Знаки осей (подъём руки вперёд = отрицательный pitch, наружу у правой руки = положительный roll, внутрь = отрицательный yaw) взяты из ванильной модели и **не проверены в игре**: если какая-то поза выглядит зеркально, поменяйте знак в `ANIMS` — другого кода менять не нужно.
* Формат JSON — Emotecraft v3 (`version 3`, `emote.moves`, части `head/torso/rightArm/leftArm/rightLeg/leftLeg`, углы в радианах при `degrees: false`); библиотека читает его и формат GeckoLib, файлы лежат в `assets/<ns>/player_animation/`. Схему (имена частей, согласованность `beginTick/endTick/stopTick`, `returnTick` циклов, радианы) проверяет `tools/validate.py`. Точное описание схемы в открытых источниках не нашлось, поэтому она восстановлена по формату Emotecraft; если библиотека отвергнет файл, в логе будет сообщение загрузчика ресурсов.

## Версия библиотеки 1.0.2-rc1+1.20 (1.1.2)
* API сверено с тестовым модом библиотеки: `PlayerAnimationFactory.ANIMATION_DATA_FACTORY.registerFactory(id, приоритет, фабрика)`, `PlayerAnimationAccess.getPlayerAssociatedData(игрок).get(id)`, `PlayerAnimationRegistry.getAnimation(id)`, `KeyframeAnimationPlayer`.
* Переходы теперь через `ModifierLayer.replaceAnimationWithFade(AbstractFadeModifier.standardFadeIn(тики, Ease.INOUTSINE), …)`: 2 тика между навыками, 6 тиков при входе/выходе из стойки Полудракона — нет «скачка» позы.
* Состояние стойки Полудракона хранится по слою (`WeakHashMap`), а не по UUID: у пересозданного игрока (вышел из зоны видимости и вернулся) слой новый, и стойка запускается заново.
* `mods.toml`: диапазон версии библиотеки `[1.0.0,)`. Раньше было `[1.0.2,)`, но по правилам сравнения версий Forge `1.0.2-rc1` меньше `1.0.2`, то есть именно эта сборка отвергалась бы загрузчиком.
* Ходьба/ноги не анимируются (слой анимирует только руки, торс и голову); ваниль-свинг руки DK-способностей остаётся и перекрывается слоем.

## Стойки монаха
У монаха отдельный слой стойки с приоритетом ниже слоя одноразовых навыков:
`monk_stance` (Текучая), `monk_stance_tiger` (Тигр) и `monk_stance_crane`
(Журавль) — циклические позы; `monk_stance_shift` — короткая одноразовая
анимация перехода. Сервер синхронизирует идентификатор стойки также клиентам,
наблюдающим за игроком. Генераторы `tools/gen_monk.py` и `tools/gen_anims.py`
создают JSON, а `tools/validate.py` проверяет наличие и схему этих ресурсов.
